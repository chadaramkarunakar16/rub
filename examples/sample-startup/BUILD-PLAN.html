Voice note to record

  1. Rep taps record and speaks
  2. App uploads audio to API
  3. API stores audio and queues a job
  4. Worker transcribes the audio
  5. Worker extracts fields as JSON
  6. API saves the record
  7. App shows the record for review

You are helping me build my own product: Sampleo.

A mobile-first app where a field rep records a voice note after a visit and it becomes a structured CRM record.

Stack:
- frontend: Next.js (responsive web app / PWA)
- backend: FastAPI (Python)
- database: PostgreSQL (Supabase)
- auth: Supabase Auth
- ai: Speech-to-text API + LLM with JSON output
- hosting: Vercel + Render

Data model:
- users(id, email, team_id)
- visits(id, user_id, customer_name, audio_url, transcript, created_at)
- records(id, visit_id, fields_json, status)

API:
- POST /visits: Upload audio and create a visit
- GET /visits: List my visits
- PATCH /records/{id}: Edit and confirm a record

Before you show it to users

  • Privacy note explaining audio storage and deletion
  • Rate limits on uploads
  • Error monitoring
  • 5 real users testing for a week

Risks to watch

  • Speech accuracy on accents and noise
  • LLM cost per recording
  • Storing voice data needs consent and a deletion option
